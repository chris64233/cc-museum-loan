# cc-museum-loan

管理馆藏品、保护条件和机构借展资料，支持借展机构一次申请多件馆藏品，并在保护条件满足后**原子批准整组借展**。

## 开发环境

- JDK 21
- Spring Boot 4.1.1
- Maven Wrapper 3.9.9
- H2

## 本地运行

启动服务：

    ./mvnw spring-boot:run

运行测试：

    ./mvnw clean test

## 领域模型

- **馆藏品（Artifact）**：唯一藏品号 `catalogNo`、可外借状态 `loanable`、允许温度区间、允许湿度区间、运输风险等级（LOW/MEDIUM/HIGH）。
- **借展机构（Institution）**：唯一机构编号 `code`、可承担的最高风险等级 `maxRisk`。
- **借展申请（LoanRequest）**：机构、多件不重复藏品、借展起止日期（闭区间）、承诺温湿度区间、运输方案风险等级；状态机为 `PENDING → APPROVED / REJECTED`，`APPROVED → CANCELLED`。
- **审计记录（LoanAuditLog）**：申请提交、批准、拒绝、取消均留痕，拒绝与取消保留原因。
- **幂等记录（IdempotencyRecord）**：状态操作的幂等键、内容哈希与首次响应快照。

## 主要业务规则

### 申请（POST /api/loans）

申请内容完整校验通过后才保存为待审批（PENDING）：

- 机构必须存在；藏品号列表非空、不重复且全部存在；
- 起止日期均必填，结束日期不早于开始日期；
- 承诺温湿度区间各自下限不大于上限；
- 每件藏品当前可外借；
- 机构最高可承担风险等级 ≥ 运输方案风险等级，且 ≥ 每件藏品的运输风险等级；
- 承诺温湿度区间完全落在每件藏品的允许范围内（边界相等视为满足）。

### 批准（POST /api/loans/{id}/approval）

批准时在**同一事务内**对整组藏品重新检查，全部通过才生效，任一失败则整组失败、申请保持待审批：

1. 申请必须处于待审批状态；
2. 每件藏品仍可外借；
3. 机构风险能力仍足够（同申请校验规则）；
4. 承诺环境仍完全落在每件藏品允许范围内；
5. 每件藏品不存在日期重叠的**已批准**借展。日期区间为**闭区间**，同一天交接也视为冲突（如 10-01~10-10 与 10-10~10-20 冲突，10-11 起借则不冲突）。

**原子性与并发**：批准事务先按藏品 id 升序对整组藏品加悲观行锁（`PESSIMISTIC_WRITE`），再执行上述检查并提交。两个申请并发争抢任一相同藏品时，锁保证检查与提交串行化，至多一个成功；失败方整组不预留任何藏品。

### 拒绝（POST /api/loans/{id}/rejection）

- 仅待审批申请可拒绝，必须提供原因；
- 原因写入申请并记录审计；被拒绝的申请不占用任何藏品。

### 取消（POST /api/loans/{id}/cancellation）

- 仅**尚未开始**（开始日期晚于当天）的已批准借展可取消，必须提供原因；
- 取消即释放全部藏品（已批准占用从借展日历中移除，同区间可再次出借）；
- 原因写入申请并记录审计。

### 幂等（Idempotency-Key 请求头）

- 申请、批准、拒绝、取消四类状态操作必须携带 `Idempotency-Key` 请求头；
- 相同幂等键 + 相同请求内容重放：返回首次执行的原结果（原状态码与响应体），不产生重复副作用；
- 相同幂等键 + 不同内容（含不同操作类型）：返回 **409 Conflict**；
- 幂等记录与业务写入在同一事务提交，数据库唯一约束兜底并发同键请求。

### 查询

- `GET /api/loans/{id}`：申请详情（机构、藏品清单、承诺条件、状态、原因、审计记录）；
- `GET /api/loans/artifacts/{catalogNo}/calendar`：藏品借展日历，按开始日期升序列出该藏品全部已批准占用区间。

### 基础资料登记

- `POST /api/artifacts`：登记馆藏品（藏品号唯一，重复返回 409）；
- `POST /api/institutions`：登记借展机构（机构编号唯一，重复返回 409）。

## 错误码约定

| 状态码 | 场景 |
| --- | --- |
| 400 | 请求体/参数校验失败、缺少幂等键 |
| 404 | 申请或藏品不存在 |
| 409 | 幂等键内容冲突；批准/拒绝/取消业务规则不满足（含日期重叠、不可外借、风险不足、状态不允许） |

## 数据与事务

- JPA + H2，实体唯一约束（藏品号、机构编号、申请内藏品唯一、幂等键唯一）由数据库保证；
- 所有状态变更在单事务内完成，整组批准要么全部生效要么全部回滚；
- 审计记录与状态变更同事务写入，保证留痕不丢失。
